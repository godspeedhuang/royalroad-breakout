七個發現

資料單位

一列是一章，小說層級的數字在書內固定

followers、total_views、ratings 在同一本書的所有章節完全相同，所以做小說層級分析要先用 fiction_id 去重。每本書章數中位數是 5，23.6% 的書只有 1 章，66.7% 至少有 3 章。

缺值

五個評分欄位和 pages 一筆資料都沒有

overall、style、story、grammar、character 五個 score 與 pages 在 86,959 本書中都是 null。ratings 和 favorites 是「次數」，不是分數。status 有 82.5% 缺值，只有約 17.5% 的書標了連載中或已完結。

熱度

極度右偏，約四分之一的書沒有任何 follower

followers 中位數 3，P90 116，P99 約 2,386；26.8% 的書是 0。views 與 followers 的 Spearman 相關是 0.84，兩者幾乎在量同一件事。

洩漏

連載越久越熱門，年資是最大的混淆變數

在至少 3 章的 57,997 本書裡，followers 達前 10%（≥ 244）的比例，從連載不到 3 個月的 2.7% 升到超過 3 年的 12.8%。章數與 followers 的 Spearman 相關是 0.56。followers 是爬取當下的累積值，不是第 1 章剛發布時的值。

缺值模式

ratings 和 favorites 的缺值集中在冷門書

0 個 follower 的書裡，92% 的 ratings 是 0 或缺值；到 1,000 以上就幾乎都有。缺值不是隨機的，代表「沒人評」。

漂移

AI 輔助內容在近年快速增加

標 AI-Assisted 的新連載比例，2022 年是 0.3%，2023 年 5.1%，2025 年 22.2%。另有 1.7% 的書標 AI-Generated。資料量也偏向近年：2024 年一年就有 395,598 章。隨機切分會讓測試集和訓練集分布不同，要用時間切分檢查。

文字量

前三章的文字量夠當模型輸入

單章字數中位數約 1,866（以空白粗估），少於 100 字的章節只占 0.6%。前三章合計中位數約 5,082 字。

Y 是什麼

資料集本身沒有現成的 Y，要自己定義。我建議的主要目標：

選項定義用途與問題
主要 Y（建議）同一季度開始連載的書之中，followers 排名前 10% = 1，其餘 = 0；只用至少 3 章的書二元分類，正例約 10%（依定義）。用「同期」比較可以去掉連載年資的影響。
簡化版followers ≥ 244（全體前 10%）好懂，但舊書占便宜：連載超過 3 年的書進前 10% 的比例是 12.8%，不到 3 個月只有 2.7%。
連續版log10(1 + followers)做迴歸，可以報告 R² 或排序品質；仍受年資影響。
副目標warnings 多標籤，或是否有 AI-Assisted內容審核分流用。標籤現成，不需要自己定義。

不能當 Y 的：五個 score 與 pages（全空）。total_views、favorites、ratings 與 followers 同步（相關 0.83 到 0.89），拿來當 Y 的替身可以，但不能同時放進 X。

同期排名怎麼運作

每個季度的書數和門檻差很多，所以要先看分組夠不夠大、門檻是否穩定：

  • 早期季度太小：2013 Q1 到 2014 Q3 的 7 個季度每季不到 200 本，前 10% 只有 2 到 8 本，排名不穩。建議排除，或合併成一組，只損失 235 本。
  • 2015 Q1 到 2024 Q2 的門檻大致在 230 到 700 之間，每季至少 376 本，這段最適合當主要資料。2024 下半年起門檻開始往下掉（177、119）。
  • 2025 年的兩個季度要小心：書數最多（5,061 與 5,436 本），但連載才幾個月，門檻只有 67 和 20。這些書的「前 10%」其實是「這幾個月內比較早被追蹤的」，意義和老書不同。建議把最近兩季拿來當時間切分的測試集，或乾脆不用。

多模態怎麼用

這個資料集的「模態」是文字、類別標籤和圖片網址。圖片只有封面一種，而且只有網址，要自己下載才有影像。

模態欄位怎麼變成特徵要注意
文字（短）title、descriptionTF-IDF，或預訓練句子 embedding簡介有時寫「每週日更新」「加入 Discord」，這是作者行為，不是故事內容。
文字（長）前 3 章的 text（中位約 5,082 字）切成段落，各段取 embedding 後平均；或只取前 N 個 token必須只用「前 3 章」，不能用全部章節，否則等於偷看之後的內容。
多標籤類別tags（64 種）、warnings（6 種）、is_originalmulti-hot 向量較舊的書常沒有標警示：2013 年有 95% 的書警示是空的，2025 年約 29%。這是標籤習慣，不是內容變乾淨。
圖片cover_url下載封面，用預訓練影像模型（如 CLIP）取 embedding26.5% 的書沒有自訂封面（預設圖），舊書特別多：2013 年約 93%，2025 年約 16%。要加一個「有無封面」旗標，並檢查下載失敗率。
數值與時間release_datetime、各章字數星期、時段、前 3 章間隔天數、前 3 章字數這些在第 3 章發布時就已知，屬於可用特徵。

不能放進 X 的欄位：total_views、average_views、favorites、ratings、status，以及章節總數。它們都是爬取當下才知道的結果，等於把答案給模型。

建議的比較順序：只用 tags 的 baseline、加上 TF-IDF、改成 embedding、再加封面。每一步報告相對上一步的提升，這樣可以回答「文字與圖片各自值多少」。

對 Project 1 的建議

  • 目標改用 followers。評分欄位全空，目標用「followers 是否進前 10%」，在至少 3 章的書中門檻是 ≥ 244。
  • 先處理年資。只看同一個年資區間的書，或把年資當控制變數；否則模型只是在學「誰連載得久」。
  • 用 fiction_id 分組切分。同一本書的章節不能同時出現在訓練與測試。作者平均 1.5 本，最活躍的 100 位作者只占 2.6%，所以也可以改用作者分組。
  • 檢查時間漂移。用較舊的書訓練、較新的書測試，看表現會掉多少。
  • 隱私。丟掉 author、author_url；小說全文不放進公開 GitHub repo。
  • $ 影響只能用假設。資料沒有收入或曝光成本，要靠情境與敏感度分析。
