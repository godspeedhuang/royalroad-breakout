01問題和 Y

Stakeholder 是 Royal Road 的推薦團隊：每季有兩千多本新連載，推薦位有限，第一次寫書的作者沒有前作可以參考，最容易被淹沒。

Y = top10

同一季開始連載的書裡，followers 是否 ≥ 第 90 百分位。整體 10.0% 是 1。

為什麼只跟同季比：followers 是約 2025-06-16 的單一快照，沒有成長曲線。2017 年的書累積了 8 年，2023 年的才 2 年。直接比 followers，模型只會學到「越老的書越紅」。資料裡連載不到 3 個月的書進前 10% 的比例是 2.7%，超過 3 年的是 12.8%。

樣本：2016–2024 年開始連載、至少 3 章的書，共 45,245 本。一本書一列，存在 embedding/out/books.parquet，裡面已經有 tags、作者、前三章長度，以及三種 1,536 維向量（前三章 book_vec、第一章 chap1_vec、簡介 desc_vec）。

03特徵區塊

特徵分成五塊，每塊一個字母，模型名稱就是這些字母的組合。例如 lr_SAT 是 logistic regression 用 S、A、T 三塊。

代號內容維度主模型
S 結構化tags 與 warnings 的 multi-hot、是否原創、tag 數、前三章 token 數（log）、是否被 20,000 token 上限截斷、前三章發布間隔天數（log）75用
A 作者經驗是不是第一次寫書、以前寫過幾本（log）。只算更早開始連載的樣本內書2用
T 前三章文字book_vec：前三章依 token 數加權平均的 embedding1,536用
P 前作表現作者以前有沒有任何一本進同季前 10%1不用，leak
D 簡介desc_vec + 簡介長度1,537不用，leak

P 和 D 為什麼不放：兩塊都可能偷看到未來。

  • P：前作的 followers 也是 2025 年的數字。這本書紅了，讀者會回頭追前作，前作就被拉高。等於用這本書的成功去預測這本書。
  • D：簡介是 2025 年的版本，作者紅了以後常回去改，加上「Book 2 已出」「Kindle 版」「Patreon 搶先看」。細節在 Leak 檢查。

這兩塊只拿來回答「如果允許偷看，上限有多高」，不算正式成績。

不能當特徵的欄位（事後才有）：followers、total_views、average_views、favorites、ratings、n_chapters、status、cover_url。

作者歷史怎麼算才不會偷看

全部書照 first_release 排序，按 author_id 分組，用 cumcount 算「這本之前寫過幾本」，用 shift().cummax() 算「之前有沒有任何一本紅過」。shift 保證只看更早的書。features.py 的自我檢查會確認：每位作者的第一本書，前作數一定是 0；寫最多本的作者，計數逐本 +1。

05指標：Recall@名額

推薦團隊真正的問題是「推薦位有限，有多少給對了書」。所以主要指標是名額命中率：

以 2023 年平均一季為例

  1. 這一季約 2,019 本新書，其中約 203 本日後進同季前 10%。
  2. 給 203 個推薦位（名額 = 該季熱門書的數量）。
  3. 模型照分數挑最高的 203 本，數裡面有幾本真的紅：平均 97.8 本。
  4. 命中率 = 97.8 ÷ 203 ≈ 0.48。四季合起來算。

因為名額剛好等於熱門書數量，這個數字同時是 recall 也是 precision。隨機挑大約 0.10。另外也報 AUC（整體排序好不好）和 AP。

跟隊友先前的版本不同：隊友固定 314 個名額、樣本是 2021–2023 年至少 5 章的書，兩邊數字不能直接比。

06模型：由簡到繁

每個模型都在 2022 驗證年挑超參數，挑好後用 2017–2022 重新訓練，再對 2023、2024 打分數。

規則 baseline（01_ml.py）

不用模型，編輯憑直覺就做得到的排法：

規則分數怎麼算驗證年命中率
更新最快的優先前三章發布間隔越短，分數越高0.131
熱門類型優先每個 tag 在訓練資料裡的走紅比例；一本書的分數 = 它所有 tag 的平均0.278
老作者優先以前寫過越多本，分數越高0.144

「最好的規則」用驗證年命中率選，選到熱門類型優先。

Logistic regression 階梯（01_ml.py）

StandardScaler + LogisticRegression，一次加一塊特徵：S → S+A → S+A+T → +P → +D，另外跑只用 T、只用 D。一塊一塊加，才看得出每塊多帶來多少。正則化強度 C 從 {10⁻⁴, 10⁻³, 10⁻², 10⁻¹} 用驗證年 AUC 挑：S、S+A 選到 0.01，加了 1,536 維文字後選到 0.001（維度多，需要更強的正則化）。

Gradient boosting（01_ml.py）

HistGradientBoosting，特徵是 S + A + 文字向量先用 PCA 壓到 32 維。不壓的話 1,536 維向量會淹沒 tags 這種維度少但很強的特徵。Grid：learning rate {0.03, 0.1} × max_leaf_nodes {8, 31}，300 輪；選到 0.1、8。

MLP（02_dl.py）

PyTorch：輸入 → 256 → 64 → 1，ReLU + dropout，AdamW（lr 10⁻³）、BCE loss、batch 256。最多 40 個 epoch，驗證 AUC 連 5 個 epoch 沒進步就停。Grid：dropout {0.2, 0.5} × weight decay {10⁻⁴, 10⁻²}。重新訓練時用驗證年找到的 epoch 數，跑 3 個 random seed 取平均分數。

  • mlp_SAT：dropout 0.5、weight decay 10⁻⁴、6 個 epoch，驗證 AUC 0.876
  • mlp_T：dropout 0.2、weight decay 10⁻²、2 個 epoch，驗證 AUC 0.846

文字編碼器（text-embedding-3-small）是凍結的，沒有 fine-tune，只訓練接在後面的網路。

從沒有 leak 疑慮、特徵相同（S+A+T）的三個候選裡，挑驗證年 AUC 最高的，不看測試成績：

08Leak 檢查

簡介（D）有問題

測試年 7.8% 的書，簡介裡出現 amazon、kindle、patreon、audible、audiobook、stubbed、"book 2"、"book two"、"volume 2"、discord 這類字。這些書有 45.5% 是熱門書（整體 10%），光用「有沒有這些字」這一個旗標，AUC 就有 0.652。這些字多半是作者紅了之後才加的。只用簡介的模型拿掉這些書後，AUC 從 0.873 掉到 0.837。所以 D 不放主模型。

浮水印對模型沒影響

約 6,507 本書的章節含防盜句子（清單在 embedding/out/watermark_books.csv）。測試年 9.7% 的書有，其中 11.1% 是熱門書，跟整體差不多；旗標本身 AUC 0.506，等於沒資訊。拿掉這些書後主模型 AUC 0.889，原本 0.887。所以不用為了建模重做 embedding。

還沒辦法排除的：tags 和章節內容也是 2025 年的版本，作者可能事後補 tag、在章節裡加作者留言。這個資料集沒辦法還原當時的版本。

09漂移測試：模型多久要重訓

04_drift.py 固定測試年，換不同年代的訓練資料。每個訓練窗都是連續 2 年、抽 5,000 本、重複 5 次，所以唯一的差別是「資料有多舊」。如果讓書紅的東西一直在變，資料越舊 AUC 應該越低。對 2020–2023 四個測試年都做一次，tags 模型（只用 S）和文字模型（只用 T）分開看，C 沿用驗證年選到的值。

四個測試年合起來（各測試年先扣掉自己的平均再迴歸），訓練資料每多舊一年：tags 模型 AUC 掉 0.026，文字模型掉 0.008。

tags 的規律老得快，文字的訊號比較耐用。tags 掉得快有一部分是標籤系統本身在變（例如 Progression 這個 tag 是後來才普及的），不全是讀者口味變了。給推薦團隊的建議：至少每年重訓一次。

10過程中改過的決定

建模不是一次寫好的。下面是途中發現問題、改掉做法的地方，簡報被問到時可以直接用。

  • 從零寫隊友先前有一版 Recall@10% 的程式（2021–2023、至少 5 章、314 個名額）。決定不接，重寫一套能跟 embedding 樣本對齊、時間切分一致的版本。
  • 作者特徵縮水一開始 A 放了「前作 followers 的同季百分位」平均與最大值。後來想到前作 followers 是 2025 快照，會被這本書回推，所以 A 只留經驗（寫過幾本、是不是第一次），前作有沒有紅移到獨立的 P，標成 leak。
  • 簡介拿出主模型一開始 D 在主模型裡。查簡介內容發現 Kindle、Patreon、"Book 2" 這類成功字眼，旗標本身 AUC 0.652，就把 D 改成只當上限。
  • 浮水印驗證embedding 分析時發現 2016 年的大跳動是浮水印造成的。建模時另外輸出浮水印書單，確認拿掉後主模型 AUC 不變，所以不重做 embedding，只把 2016 年排除。
  • 測試年用 2023原本的設計寫「2023–2024 都不適合當測試年」。考量 2023 已經觀察 1.5–2.5 年，只排除 2024 當補充。
  • 主模型靠驗證年選MLP 在測試年其實稍高（0.493 對 0.482），但主模型是照驗證年 AUC 先選定的，兩者差距也不顯著，所以維持簡單的 LR。

11限制與待辦

限制

  • DL 只是凍結向量上的 MLP。要說做了 deep learning，嚴格一點應該 fine-tune 文字模型（chapters.parquet 有原文），成本高一個量級。現在 MLP 跟 LR 沒差，fine-tune 也未必更好。
  • 作者經驗只算樣本內的前作。2016 年以前、或不到 3 章的前作沒算進來，「第一次寫書」會多算一些人。可以從 data/interim/fictions_47.parquet 補完整。
  • tags 和章節內容可能被事後改過，資料集無法還原。
  • 2016–2017 年每季前 10% 只有 52–60 本；followers 為 0 的書在同季排名並列。

待辦（截止 2026-11-20）

  • 簡報 5–10 頁、2 分鐘影片，對象是 Royal Road 推薦團隊。
  • README 縮成一頁。
  • 把「每季多挑中 45 本熱門書」換算成營收或讀者時間。
  • 可選：測試年改回 2022 做穩健性檢查，只要改 features.py 的 TRAIN_YEARS / VAL_YEAR / TEST_YEAR。
